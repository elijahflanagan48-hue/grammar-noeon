# Единый аккаунт NOEON: план

Сейчас у сервисов три разные системы входа: Grammar (Firebase, отдельный проект, подтверждение почты), TOEFL (свои пароли PBKDF2 в D1 `noeon-toefl`), Words и placetest. Из-за этого пароль, созданный в одном месте, не подходит в другом.

## Принцип
Один аккаунт = одна почта и один пароль на всех сервисах NOEON. Аккаунт отвечает на вопрос «кто это». Связь ученика с учителем и роль хранятся в каждом сервисе отдельно и создаются по ссылке-приглашению.

## Этапы
1. **Один Firebase-проект для всех сервисов** (тот, что уже у Grammar). Web API key публичный, каждый Worker/клиент ходит в него. 14 учеников Grammar переносить не нужно. Сделано в Grammar: вход принимает любой существующий пароль, понятные ошибки, подсказка «аккаунт NOEON найден, откройте ссылку учителя» (код NO_PROFILE).
2. **TOEFL**: ленивая миграция. При первом входе проверяем старый пароль (PBKDF2), создаём аккаунт в Firebase с тем же паролем и привязываем `firebase_uid` к строке `users`. Дальше пароль живёт только в Firebase.
3. **Words и placetest**: вход через тот же Firebase (Identity Toolkit REST, без SDK), данные остаются в сервисе.
4. **Связь с учителем**: ссылка-приглашение одна для всех сервисов (`noeon.org/join/<token>`), реестр связей в маленьком Worker `id.noeon.org`; сервисы спрашивают у него, чей ученик. До этого ссылки работают внутри каждого сервиса, как сейчас в Grammar.
5. **Один вход без повторного ввода** (по желанию): подписанный cookie на `.noeon.org`, сервисы проверяют подпись.

- Подключить репозитории Words и TOEFL к Claude (сейчас доступны только grammar-noeon и noeon-level-test).
