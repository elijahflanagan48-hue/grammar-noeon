## Схема фабрики (кратко; подробности в `docs/variety/bankgen/README.md`)

Каталог темы `content/bankgen/<тема>/`: `seeds/`, `prompts/`, `combined/`, `combined-legacy/`, `raw/`, `final/`, `reports/`, `plan.json`, `plan-legacy.json`, `master.md`, `id-map.json` (**никогда не удалять**).

Форматы заданий: gap, mini, mc, fix, which, transform.

Команды:

- `python3 -B scripts/bankgen.py validate <тема> <батчи…>`: проверка сырого ответа Gemini, отчёты в `reports/`.
- `python3 -B scripts/build_bankgen.py <тема> --date YYYY-MM-DD`: сборка банка в `data/exercises/` (нужно, чтобы файлы в `final/` точно совпадали с `plan.json`: набор батчей и размеры; старые задания темы помечаются `retired`).
- `python3 -B scripts/update_docs.py` (и `--check`), `python3 -B scripts/build_cloudflare.py`, `npm run check` (25 SKIP ожидаемо), `npm run test:browser` по необходимости.
- `python3 -B scripts/lexical_audit.py <тема> --gate 0.05` (доля редких слов ≤ 5%); `--list N` показывает самые частые.
- `python3 -B scripts/audit_variety.py --gate docs/variety/<тема>-gates.json`.
- `python3 -B scripts/lexical_repairs.py <тема> content/bankgen/<тема>/lexical-map.json`: массовая замена редких слов на простые (карта `{"words":{}, "names":{}}`; не трогает слова, которые стоят в ответах и подсказках в скобках).

### Метод legacy-seed (как добирали comparison и nouns)

1. `python3 -B scripts/bankgen_legacy.py <тема> <сколько_добавить>` создаёт `seeds/seeds-legacy.jsonl` (старые задания как сюжеты; префикс `cl`/`nl`…), `plan-legacy.json` и промпты. Влить `plan-legacy.json` в `plan.json` (батчи добавляются, `target_total` растёт).
2. Для каждой пары батчей собирается файл `combined-legacy/ATTACH_<тема>_<A>_<B>.md` (мастер-промпт + два промпта батчей). Образцы: `content/bankgen/comparison/combined-legacy/`.
3. Файл прикрепляется в Gemini; Gemini возвращает один блок кода JSONL на оба батча.
4. Ответ разбивается по батчам в `raw/`, валидируется, проблемные задания (ERROR в отчёте) выбрасываются, годные пишутся в `final/<батч>.jsonl`. Скрипт, который это делал у Claude (повторить самому):
   ```python
   # разбор: строки вида {"id":"CP27-01",...} группируем по префиксу CP27, комментарии "# check:" игнорируем
   # raw/<батч>.jsonl -> bankgen.py validate -> final/<батч>.jsonl без заданий с ERROR
   ```
   Если задание отбраковано, батч получается короче плана: в `plan.json` нужно подправить размер или дозаказать недостающие.
5. После всех батчей темы: лексический ремонт (≤5%), сборка, variety gate, тесты, `sw.js`, CHANGELOG, `update_docs.py`, `build_cloudflare.py`, `npm run check`, коммит, ребейз на `origin/main`, пуш.

Сборка новой темы требует интеграции в приложение: цели практики (теги заданий) должны быть известны интерфейсу. Для nouns это делалось так: новые цели `nn_*` в `app.js` + миграция старых целей (`NOUN_TARGET_MIGRATION`, `nounPracticeTargets`), `targetSection`, ссылки «сегодняшнее правило», `shortTopics`, `cloudflare/statistics.mjs` (регулярка раздела), тест `tests/bankgen-nouns.mjs`, порог скобок для темы в `scripts/validate_content.py`. Посмотри `git show fe4084a` как образец и повтори для comparison (теги `cmp_*`), потом для остальных тем.

## Gemini: как им управлять

Нужен чат с вложением. Тексты промптов огромные (≈40–60 КБ), поэтому вставка текстом ненадёжна; всегда прикрепляй `ATTACH_*.md` как файл.

Бандл приложения: `com.google.GeminiMacOS`. Папка обмена на Mac: `/Users/ilya/Projects/bankgen-exchange/conditionals/gemini/` (ATTACH-файлы лежат там же, скачанные ответы тоже). Если файла нет, скопируй его из `content/bankgen/<тема>/combined-legacy/`.

Порядок на одну пару батчей:

1. Новый чат (кнопка «Новый чат»).
2. «+» → «Файлы» → в окне выбора через поиск найти `<тема>_<батч>` (например `comparison_CP31`) → выбрать строку → «Открыть».
3. В поле сообщения: `Follow the attached file exactly: it contains the master prompt and two batch prompts. Produce the output for both batches as the file describes (JSONL, one code block), nothing else.` → Return.
4. Ждать 8–15 минут (иногда до 25). Готово, когда появились кнопки реакций под ответом и в поле снова иконка микрофона; прокрути чат вниз и убедись, что нет «Запрос отменён». Если «Запрос отменён» или «Что-то пошло не так» → кнопка «Повторить» (вложение сохраняется). Меню «retry» теряет вложение, так что используй новый чат.
5. **Пока Gemini генерирует, нельзя переключаться на другой чат и открывать новый**: ответ отменяется.
6. Кнопка скачивания в блоке кода → окно «Сохранить»: имя `<тема>__<БАТЧИ>.jsonl` (например `comparison__CP31_CP32.jsonl`), папка должна быть `gemini` (путь Projects/bankgen-exchange/conditionals/gemini). Если «уже существует», нажать «Заменить».
7. Проверь размер файла (обрезанный ответ маленький, около 8 КБ вместо 25–60 КБ) и `# check:`-строки в конце (их игнорируем).

Заметки по управлению Mac: после разрешения доступа к Gemini окна выбора файла хорошо работают в режиме полного контроля экрана; в фоновом режиме клики в окне «Открыть» не срабатывают, поэтому на время прикрепления файла нужен полный контроль, остальное (ожидание, скачивание, сохранение) можно делать в фоне, чтобы не мешать владельцу. Если во время работы мост к Mac пропал (например, открылся Zoom), не повторяй попытки подряд; подожди и проверь связь позже.

## Правила

- Не меняй банк conditionals и всё, что относится к соседнему чату.
- В коммитах не добавляй `git add -A` вслепую (в рабочем дереве есть неотслеживаемые вещи вроде симлинка `node_modules`).
- Слово `shall` в современных упражнениях запрещено (тест final-answer-policy).
- Не переиспользуй id; `id-map.json` хранит соответствие, не удаляй.
- Перед пушем: `npm run check` без падений, лексический gate темы ≤ 5%, variety gate, число живых заданий темы ≥ 1000.
- В конце каждого релиза: запись в `docs/CHANGELOG.md`, `sw.js` (новое имя кэша, например `grammar-v106-comparison`), `update_docs.py`, `build_cloudflare.py`.
