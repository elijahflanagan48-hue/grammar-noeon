# Фабрика банков: как наполнять остальные темы

Схема passive v7, обобщённая на все темы. Всё, что зависит от темы (ячейки решений, типичные ошибки, сцены, ограничения), лежит в `scripts/bankgen_specs.py`. Остальное (промпты, назначение сюжетов, проверка, повторные запросы) общее.

| Тема | Новых заданий | Ячеек | Пачек (40) | Сюжетов нужно |
|---|---|---|---|---|
| reported | 700 | R1–R9 | 21 | ~910 |
| comparison | 700 | C1–C9 | 20 | ~910 |
| modals | 600 | M1–M8 | 17 | ~780 |
| nouns | 500 | N1–N7 | 14 | ~650 |
| infinitive | 500 | I1–I7 | 14 | ~650 |
| speaking | 250 | S1–S5 | 11 | ~325 |
| tenses | 1515 | T1–T12 | 37 | ~1950 |

Порядок тем: reported → comparison → modals → tenses → nouns → infinitive → speaking. Интегративные задания (смесь тем) и выбор нескольких тем в фильтре добавим после того, как заполним банки по отдельным темам.

## Шаги для одной темы (на примере reported)

1. `python3 scripts/bankgen.py all reported` — план, мастер-промпт, промпты на сюжеты. Уже сделано для всех тем, файлы лежат в `content/bankgen/<тема>/`.
2. **Сюжеты.** Файлы `seed-prompts/seeds-NN.md` отправить после `master.md` в DeepSeek или в локальную модель. Ответы сохранить как `seeds/seeds-NN.jsonl`. Раннер делает это сам: `python3 scripts/bankgen_run.py seeds reported --engine deepseek`.
3. `python3 scripts/bankgen.py seeds-check reported` — дубли, баланс «зацепок», нехватка.
4. `python3 scripts/bankgen.py prompts reported` — готовые промпты пачек со своими сюжетами (`prompts/RP01.md …`). Для маленьких локальных моделей: `prompts reported --chunk 12` (пачки по ~12 заданий в `prompts-small/`).
5. **Задания.** Gemini: вставить `master.md`, затем `prompts/RPxx.md`, ответ сохранить в `raw/RPxx.jsonl`. DeepSeek и LM Studio: `python3 scripts/bankgen_run.py batches reported --engine deepseek` (или `--engine lmstudio --model <id> --small`). Раннер сам проверяет ответ и делает до двух повторных запросов на исправление.
6. `python3 scripts/bankgen.py validate reported` — отчёт `reports/RPxx.md` и промпт на исправление `reports/repair-RPxx.md`.
7. **Ревью Claude** → `final/RPxx.jsonl` (грамматика, ключи, естественность, лексика).
8. **Codex** собирает финальные файлы в банк (`codex-prompt.md`).

## Кто что делает

- **DeepSeek (API) и локальные модели (LM Studio):** сюжеты (дёшево, много) и черновики пачек для простых тем (nouns, infinitive, speaking). Локальные модели писать пачки лучше с `--small`, ошибок у них больше, зато валидатор и ревью их ловят.
- **Gemini:** основные пачки сложных тем (reported, comparison, modals, tenses), вручную через чат.
- **Codex:** сборка банка, id-map, `retired` для старых заданий, gate разнообразия по темам. Не трогать файлы банка, пока в соседнем чате идёт работа над conditionals.
- **Claude:** проверка каждой пачки, правки в `final/`, итоговый аудит и релиз.

## Что проверяет валидатор

Формат и поля, число пропусков в тексте и в `blanks`, ответ среди принятых, 4 разных варианта в `mc`/`which`, `fix` без ошибки равен исходному, метка конструкции из списка темы, сюжет не повторяется, начала предложений и имена не повторяются, не больше трети заданий с маркерами времени, глагол в скобках не больше двух раз, лексика выше уровня (тот же детектор, что в passive), доля `said` в reported.

Два замечания: имена в начале предложения детектор лексики иногда принимает за редкие слова (это предупреждение, не ошибка). Лексический gate для новых тем подключим к `npm run check` так же, как для passive, когда банк темы будет собран.


## Сборка проверенного банка

```sh
python3 -B scripts/build_bankgen.py reported --date 2026-11-22
python3 -B scripts/update_docs.py
npm run check
npm run test:browser
```

Сборщик принимает только `final/*.jsonl`, проверяет комплектность по `plan.json`, поля, конструкции, ключи и уникальность сюжетов. При ошибке входных данных файлы банка не записываются. Форматы: gap/mini → open_brackets, mc/which → multiple_choice, fix → error_fix, transform → direct_to_reported для Reported и transformation для остальных тем.

`id-map.json` хранит соответствие исходного ID и `<код>-<ячейка>-NNN`; не удаляйте его между выпусками. Повторная сборка с той же датой стабильна. Отозванные задания сохраняются с retired, их ID не переиспользуются. Необязательный `keep.txt` содержит ID старых заданий, которые нужно оставить активными (по одному на строку; комментарии начинаются с #).

Меняются только части выбранной темы, общий манифест и текущая сводка выпуска. Смешанные части банка и конфликты ID блокируют запись. `passive_v7_status` сохраняется. Сборщик не публикует, не коммитит и не меняет final. Подключение фильтров каждой следующей темы нужно проверить отдельно: конструкционные теги должны быть известны её интерфейсу. Для Reported это сделано и проверяется в tests/bankgen-reported.mjs.

## Генерация через Gemini CLI

`scripts/run_bankgen_gemini.py` передаёт мастер и промпт на stdin официального Gemini CLI, сохраняет исходный запрос/ответ в `private/bankgen-topup-20261124/gemini-runner/` и пишет только проверенные черновики в seeds/ или raw/. Файлы final/ и публичный банк раннер не меняет. Неполные ответы, неверные ID, неизвестные hooks, повторные сюжеты внутри пачки и структурные ошибки заданий блокируют сохранение. Повторный запуск проверяет и пропускает уже готовые черновики.

```sh
python3 -B scripts/run_bankgen_gemini.py probe --auth api
python3 -B scripts/run_bankgen_gemini.py seeds modals --auth api --only 1,2 --workers 2
python3 -B scripts/run_bankgen_gemini.py batches speaking --auth api --only SP01,SP02 --workers 2
```

Для API-режима положите `GEMINI_API_KEY=...` в игнорируемый файл `private/bankgen-topup-20261124/gemini.env` (ключ не отправлять в чат и не коммитить). Настройки API-авторизации изолированы от пользовательских настроек CLI. Устанавливается явная модель `--model` (по умолчанию `gemini-2.5-pro`); Auto и Flash не используются, фактическая модель проверяется в ответе. Встроенные инструменты и MCP отключены: модель только генерирует текст. Другой установленный Gemini CLI можно указать через `--cli`.

На 24.11.2026 проверены версии Gemini CLI 0.70.0 и 0.71.1: существующий OAuth-вход возвращает `This client is no longer supported for Gemini Code Assist for individuals`. Встроенный Antigravity CLI после OAuth возвращает отказ по доступности сервиса для текущего аккаунта/региона. Успешная генерация через CLI до предоставления рабочего способа авторизации не подтверждена. Штатные варианты: [Gemini API key или доступный Google Cloud/Google аккаунт](https://geminicli.com/docs/get-started/authentication/). Обходы ограничений не применяются.
