Ты инженер сайта Grammar NOEON (репозиторий grammar-noeon, ветка main). Задача: подключить к сайту готовый банк упражнений Conditionals и открыть практику по теме. Работай как для предыдущих тем (infinitive, modals, reported): те же механизмы банка, версий, практики, назначений, серверной проверки и тестов. Образец — как подключён infinitive (scripts/build_infinitive_bank.py, content/, bank-versions, tests).

## Вход
- `content/bankgen/conditionals/final/CD01.jsonl … CD25.jsonl` — 804 проверенных задания, формат описан в `content/bankgen/conditionals/master.md` и `scripts/bankgen.py` (поля id, cell, format, level, prompt, explanation_ru, blanks/options/pairs/items/…, метки `construction`, у gap/mini — метка в каждом blank). Файлы не правь; если нашёл ошибку в задании, перечисли id в отчёте.
- `docs/conditionals/EXERCISES-PLAN.md` — ячейки C1–C11, цели практики (`cd_zero`, `cd_first`, `cd_conj`, `cd_second`, `cd_third`, `cd_mixed`, `cd_implied`, `cd_inversion`, `cd_wish`, `cd_unreal`, `cd_all`) и метки конструкций `cd_*` (совпадают с чипами карты правила).

## Что сделать
1. Сборщик `scripts/build_conditionals_bank.py`: из final/ собирает банк Conditionals в формат сайта (по образцу infinitive), с версией `conditionals-2026-11-22.1`, уровнями basic/medium/advanced, целью практики по ячейке и метками конструкций. Для gap/mini каждый пропуск проверяется по `accepted_answers` (все варианты, сокращения как заданы, без автодогадок).
2. Форматы gap, mini, mc, fix, which, transform работают как существующие типы (open_brackets, multiple_choice, error_fix и т.д.; подбери соответствия). Новые форматы реализуй в движке, на десктопе и мобильном:
   - `fact` — как which/multiple choice (один верный вариант);
   - `match` — соединить 4 начала с 4 концами (pairs; в интерфейсе концы перемешаны);
   - `sort` — разложить 6–8 предложений по 2 группам;
   - `bank` — банк слов, `___` в тексте, 2 лишних слова (answers по порядку);
   - `hunt` — нажать на неверные предложения (wrong), после проверки показать fixes;
   - `order` — подключить к существующему word_order; принимаются все `accepted_answers`.
   Подсказок до ответа нет. После ответа показывай `explanation_ru`. Серверная проверка и сохранение ответов для новых форматов — как у остальных (схема D1 не меняется, если можно обойтись).
3. Практика: в `GRAMMAR_SECTIONS.conditionals` убери `soon: true`, подключи «Практика →» и страницу практики с целями `cd_*`; на карте/теории замени «Практика по этой теме готовится» на ссылку в практику. Чипы конструкций ведут в практику по метке, если фильтры уже умеют. Банки свободной практики и назначений не должны пересекаться (как у других тем: используй существующий механизм разделения; если его нет для Conditionals — добавь и проверь тестом).
4. Лексический гейт: подключи `scripts/lexical_audit.py` для Conditionals в `npm run check-all` (сейчас скрипт не находит тему — добавь её).
5. Тесты по образцу других тем: структура банка, покрытие (каждая метка `cd_*` ≥ 8 заданий, в каждой цели практики есть задания всех уровней), проверка ответов (все accepted_answers засчитываются, неверные нет), новые форматы в браузерном тесте на 390px и десктопе, нет пересечения бесплатной практики и назначений.
6. Обнови PROJECT-STATUS.md, docs/CHANGELOG.md, версию PWA/кэша (sw.js), манифесты банка.

## Правила
- Не меняй содержание заданий и правило. Не трогай другие темы.
- Запусти `npm run check` / `npm run check-all` и браузерные тесты, исправь всё красное.
- Не деплой и не пушь. Закоммить локально, в отчёте: что собрано, число заданий по форматам и уровням, результаты проверок, найденные ошибки в заданиях (id). Деплой сделает Claude.
